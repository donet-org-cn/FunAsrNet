# 本机 CPU 第三轮优化与原版对比（2026-10-12）

**本页为历史快照。** 当前构建的本机纯 CPU 对照见 [第五轮记录](cpu-round5-20261012.md)。

继续在 i7-12700 本机优化纯 CPU。与同轮上一版 `48f2fc5` 对比，28 秒 ASR 耗时减少 **12.0%**，Huayan 减少 **18.2%**，AISHELL3 减少 **9.0%**。两条短句 ASR 只减少约 3%，提升有限。

本次 ASR 为原版 CPU 的 **1.15–1.18 倍耗时**，TTS 为 ORT CPU 的 **1.47–1.51 倍**。仍有项目超过原版 1.5 倍耗时。**尚未全面持平，也未达到原版一半耗时。** “慢 50% 以内”只是本次小样本中位数的口径，不能作为尾延迟或其他输入的保证。

- Windows x64、Intel Core i7-12700、.NET 10.0.12、四线程、亲和性 `0x55`，全部正式数据关闭 GPU 和性能跟踪。
- ASR：同一 F16/Q8_0 模型与音频；双方关闭提示词缓存，最大 128 token。原版固定 Fun-ASR `0339018ba74a7defa3b6b6a96718d17b816be77b`、llama.cpp `8086439a4cea94c71a5dfb8fe4ad1546aebd640f`，MSVC 19.44、AVX2/FMA/AVX-VNNI、OpenMP；GPU 层数零。
- TTS：相同音素 ID，Huayan 0 号和 AISHELL3 50 号，语速 1，两项随机度 0。对照为 ORT 1.23.2 CPU，intra-op 4、inter-op 1、顺序执行、全部图优化。
- ASR 计特征、编码和解码的完整调用；TTS 计模型 Run，排除文本前端、封装和重采样。均排除模型加载、输入读取、文件写入与预热，不是首次请求延迟。
- 每个输入采用“上一版、本次、原版、原版、本次、上一版”六个独立进程块；每块预热一次，短 ASR/TTS 每块正式五次，长 ASR 每块三次。共 **138 次正式测量、30 次预热**。每种实现的短输入十次、长输入六次，最近秩 P95 在该样本量下等于最大值。

## 保留的优化

1. x64 注意力复用两条查询和四条键，使用 256 位向量；值矩阵按头连续打包、两条查询共享加载。点积保留原双向量的分组顺序，各输出通道保留逐帧累加次序。
2. x64 Softmax 和 SwiGLU 默认使用八路向量指数，Softmax 分母仍为双精度。ARM 默认指数策略保持原设置。`FUNASRNET_VECTOR_EXP=0` 可用于标量指数诊断。
3. 转置卷积按输出采样相位计算短卷积，减少完整展开矩阵与搬运；支持条件以外继续使用通用实现。`FUNASRNET_LEGACY_TRANSPOSE_CONV=1` 可回退。
4. 每组至少 192 个输出通道的直接卷积使用八通道乘八采样点块，其余保留四通道乘十六采样点。两个内核保持同一 FMA 累加顺序，本机两种模型波形逐样本一致。`FUNASRNET_AVX_CONV8=0` 可回退；已有内部卷积回退开关也覆盖它。
5. 连续加减乘除在循环外确定运算；大 LeakyRelu 按独立块并行。Tanh 使用向量指数和小输入多项式，保留非数、无穷与零符号的定义。

量化点积的四块共同归约没有稳定收益；另一个浮点累加重排方案也未保留。Q8 权重、激活量化和逐三十二项算术保持上一版。八通道卷积对窄输出的实验有退化，最终按通道规模选择内核。诊断轮次没有计入正式性能表格。

Release 数值检查 **1,796,444 项**通过；关闭 AVX2 后的回退检查 **1,792,978 项**通过。新检查使用双精度散射卷积参考，覆盖批次、分组、大输出通道尾块、非整除核、非对称填充、输出填充和膨胀；激活覆盖极小值、边界、非数、无穷、负零与并行尾块。既有注意力精确对照和 Q8 极值检查继续通过。

本机 CPU 完整服务 46 项 DemoChecks、AISHELL3 全部 174 位发音人的 530 项检查、134,474 项 GPU 数值检查和三份 GPU ASR 回归通过。GPU 转写与上一版相同，沿用历史标点差异说明；没有重新宣称 GPU 性能。这些额外检查和带 profile 的轮次不计入 138 次正式测量。服务检查数量按日志中的 PASS 项计数；此前的 61 是包含诊断输出的日志行数，现已更正。

本次只验证 Windows x64，未部署或重启远端。固定样例一致性不等于真实浏览器麦克风识别率提高；RK3588 与真实语料 CER/WER 仍需各自验收。

## 构建来源与复测

上一版源提交为 `48f2fc531aac4f0a336e304f83ccf4d25e9dbfc0`，二进制散列见 summary 的 `buildManifest`。本次构建源码散列见 [source-sha256.json](benchmarks/20261012-cpu-round3/validation/source-sha256.json)，全部证据散列见 [SHA256SUMS.txt](benchmarks/20261012-cpu-round3/SHA256SUMS.txt)。模型和输入散列继承同一基线；输入文件与模型没有随仓库分发。

原版构建方法与完整命令沿用 [上一轮 CPU 记录](cpu-followup-20261012.md)。本次 `asr` 子命令新增 `--profile`，按权重形状与注意力阶段汇总毫秒，只用于诊断；正式计时不带它。

```shell
dotnet build FunAsrNet.sln -c Release
dotnet run --project tests/FunAsrNet.Checks -c Release --no-build
dotnet run --project tools/FunAsrNet.CodeStyle -c Release --no-build -- .
dotnet tools/FunAsrNet.Benchmarks/bin/Release/net10.0/FunAsrNet.Benchmarks.dll asr models input.f32 5 --affinity 0x55
dotnet tools/FunAsrNet.Benchmarks/bin/Release/net10.0/FunAsrNet.Benchmarks.dll tts models huayan.i64 huayan 5 output.f32 --threads 4 --affinity 0x55
```

对照 ASR 前须设置 `FUNASRNET_DISABLE_PROMPT_CACHE=1`。正式顺序、轮数、原生日志和波形对照均已保存在证据目录。
