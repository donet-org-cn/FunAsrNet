# GPU 第七轮优化与 CPU/GPU 完整对比（2026-10-12）

本轮相对 `470bd033264dd68856e4d4509b981d411949b073`，减少编码器的 GPU 往返，优化 FP32 与 Q8 内核，并在本机重测 CPU、Vulkan 和原版 CPU/CUDA。默认 CPU 推理保持纯 C#。**GPU 仍未追平原版，不能将这些后端差异解释为语言优劣。**

原版 ASR CPU 使用固定 Fun-ASR/ggml 的 AVX2/FMA/VNNI 构建；GPU 为相同上游计算图的 **C++ CUDA 编码器 + 解码器适配**。上游 Windows 入口本身不默认启用这条 GPU 路径。TTS 为同模型 ORT 1.23.2 CPU/CUDA，CUDA 禁用 TF32；仍保留 ORT 必要的 CPU 辅助节点。版本、构建来源与适配范围见 [原版 GPU 对照](gpu-native-comparison-20261012.md) 和 [CPU 对照](cpu-followup-20261012.md)。

本轮 C# CPU 热态相对上一版约 -0.8%～+1.9%，没有新的整体加速；这些 ASR 输入仍略快于原版 CPU，TTS 仍为 ORT CPU 的约 1.30 / 1.44 倍耗时。C# Vulkan 的两种 TTS 也仍慢于当前 C# CPU，不能只用它相对历史版本的加速说明已有 GPU 优势。

| ASR 5.616 秒 PCMU | 0.496 | 0.407 | 0.116 | 17.8% | 3.53 倍 |
| ASR 28.000 秒重复样例 | 1.648 | 1.344 | 0.263 | 18.5% | 5.11 倍 |
| ASR 6.000 秒原始 PCM | 0.406 | 0.346 | 0.098 | 14.8% | 3.54 倍 |

五份 ASR 的 GPU 中位数减少 **14.8%～19.4%**，Huayan 减少 **8.0%**，AISHELL3 减少 **3.9%**。当前仍为同轮原版 GPU 的 **3.14～5.50 倍耗时**，尚未达到追平目标；TTS 的小幅收益也不能证明各种输入都有同样改善。

优化包含以下四项，表格计量它们的合并效果，不将总收益分别归因于某一项：

1. 编码器的 `Linear → ReLU → Linear` 使用一次提交，两个描述符集合和计算屏障保证依赖；只回读最终结果。缓存同时保护两层权重，不支持的布局、形状或容量回退原路径。默认 CPU 的运算与工作区释放顺序保留。
2. FP32 内核用四个向量存放累加器，展开内层 K 循环，保持每个输出原有的 K 次序及 FMA/分离乘加规则。
3. 查询并启用整数点积特性后，Q8 使用打包的有符号四字节点积；32 元素分组、缩放与浮点累加顺序不变。没有重新量化或引入 FP16/TF32 计算。特性依据 [Vulkan feature 定义](https://docs.vulkan.org/refpages/latest/refpages/source/VkPhysicalDeviceShaderIntegerDotProductFeatures.html) 和 [GLSL 扩展](https://raw.githubusercontent.com/KhronosGroup/GLSL/main/extensions/ext/GLSL_EXT_integer_dot_product.txt) 核对。
4. Windows 的栅栏等待先最多主动轮询 100 微秒，再阻塞等待，减少短计算的唤醒开销；代价是等待期间占用 CPU。其他系统默认不轮询。

短 PCMA 每次提交从 **1,198 降到 1,125**，连续投影 73 次；热态上传从 **115,414,272 降到 57,046,272 字节**，回读从 **198,594,560 降到 140,226,560 字节**，两方向各减少 58,368,000 字节。904 次 Q8 同步调用仍在，解码器和其他 CPU 中间处理继续限制整体速度。尚不是完整图驻留 GPU。

`FUNASRNET_VULKAN_RELU_CHAIN=0`、`FUNASRNET_VULKAN_INTEGER_DOT=0` 分别可关闭连续投影和整数点积；`FUNASRNET_VULKAN_SUBGROUP_Q8=0` 强制旧标量行内核。`FUNASRNET_VULKAN_SPIN_US=0` 关闭轮询，可设置 0–500。比较入口清除继承的实验选项，正式测量使用默认配置。

“模型/后端初始化”是各基准的 `load` 边界：C# 包含模型读取/解析、上下文、可选 Vulkan 后端及基准的强制 GC；原版执行自身的 GGUF/mmap 或 ORT 会话初始化。ASR 行包含编码器与解码器两份模型。Vulkan 权重首次上传在首次推理内；原版 CUDA 和 ORT 的部分准备在初始化内。因此两列要结合看。

文件缓存和驱动缓存均未清空，不含进程启动、音频输入读取、Web 服务启动、VAD 和前端。**这些是新进程内的分阶段观察，不是冷盘加载或完整首次请求延迟。** ORT 加载阶段还进行图优化，不能仅凭初始化较长判断其推理较慢。

本轮没有进一步改善模型读取速度。上述短 PCMA / Huayan / AISHELL3 的 GPU 初始化观察分别为 **1.034 → 1.108、0.332 → 0.411、0.291 → 0.378 秒**，增加约 0.074～0.087 秒；新内核的初始化成本需要继续优化。初始化加首次推理分别为 **3.529 → 3.478、0.881 → 0.942、0.681 → 0.785 秒**。启动观察只有两个进程样本，不能用热态收益宣称启动同幅度加速，两个 TTS 的启动总耗时本轮反而增加。

## 协议与正确性

CPU/GPU 分别按 before/after/native/native/after/before 串行执行；每进程首次调用记录为预热，随后五次正式调用。每套 7 个项目、42 个进程、210 次正式调用，合计 **420 次正式调用、84 次首次调用及 84 次初始化记录**。全部慢样本保留。P95 使用最近秩，十个样本时等于最大值；这些样例不足以估计生产尾延迟。

ASR 双方关闭固定提示词缓存、最大 128 token。五份输入在各自 CPU 或 GPU 对照中三方逐字一致；新旧 C# 的 token 数不变。短句的 GPU 路径少句末句号，与 CPU 的八 token 输出不同，是已有路径差异，未当作本轮优化收益。原版 CUDA 的内部激活/累积可能采用不同精度，不宣称其与 Vulkan 的内部浮点运算完全相同。

两份 ASR 额外数值验证共 **53 个中间张量快照**，含编码器输出，与上一版散列逐项相同。两种 TTS 新旧 C# GPU 波形逐位相同，CPU 波形与原版的验收也通过；原版 CUDA 误差按未放宽的原阈值检查，逐次长度、最大误差、RMSE、余弦见 `parity-*.jsonl`。波形样本数为 Huayan 69,376、AISHELL3 28,928。

完整解决方案 Release 构建零警告、零错误；数值检查 **9,373,113** 项、关闭 AVX2 **9,178,432** 项通过。GPU 默认、关闭整数点积及旧标量内核分别通过 **146,347** 项，覆盖链式与独立提交的逐位比较、缓冲扩容、缓存淘汰、动态矩阵及卷积。最后的 Vulkan 扩展列表容量修正经最终构建 GPU 检查和整套 GPU 复测验证。源码中文注释与格式检查通过。

## 复测与证据

使用 [C# 对比入口](../tools/FunAsrNet.Compare/README.md)，不依赖 Python。`summary.json` 的 `groups` 记录热态，`startupPhases` 记录加载、首次推理和两者之和；命令、输入/模型/二进制散列及原始 UTF-8 JSONL 随报告保留。

```powershell
dotnet build FunAsrNet.sln -c Release -p:NuGetAudit=false
dotnet tools/FunAsrNet.Compare/bin/Release/net10.0/FunAsrNet.Compare.dll cpu --output artifacts/gpu-round7/final-cpu --before artifacts/gpu-round7/before/FunAsrNet.Benchmarks.dll --subjects sip-short-pcma,sip-zh-pcmu,sip-repeated-pcma,sip-official-short,sip-official-pcma,huayan,aishell3 --repeats 5
dotnet tools/FunAsrNet.Compare/bin/Release/net10.0/FunAsrNet.Compare.dll gpu --output artifacts/gpu-round7/verified-gpu --before artifacts/gpu-round7/before/FunAsrNet.Benchmarks.dll --subjects sip-short-pcma,sip-zh-pcmu,sip-repeated-pcma,sip-official-short,sip-official-pcma,huayan,aishell3 --repeats 5
```

`before` 是 `470bd03` 的独立 Release 目录；模型、输入和原生二进制需按原版对照说明准备，不随仓库分发。输出目录不得已存在；重新测量应换新目录名。着色器编译器 glslang 16.6.0，参数 `-V --target-env vulkan1.1 -S comp`，整数点积变体另加 `-DINTEGER_DOT=1`，源码和编译字节码都保留在 Vulkan 项目中。

[完整证据](benchmarks/20261012-gpu-round7) 包含 [分阶段汇总](benchmarks/20261012-gpu-round7/metrics.json)、源码散列、manifest 和 SHA-256 索引。正式测量 JSONL 按原字节保存，诊断日志统一 UTF-8/LF 并去除行尾空白，空日志和音频二进制不提交。调整参数的试验及扩展列表修正前的候选复测留在本机 `artifacts/gpu-round7`，没有混入最终表格。

本轮仅在用户本机测量，没有更新或重启远端 RK3588。原始 PCM、PCMA 两条补充输入是短句的格式变体，28 秒输入是重复样例；结果不能推广到 Mali GPU、自然长语音、实时麦克风识别率或并发服务容量。
