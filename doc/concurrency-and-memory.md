# 并发与内存所有权

## 推理调度

每个 `FunAsr` 包含独立的特征提取状态、临时工作区、解码位置、前缀及 KV 缓存。每个 `MandarinTts` 包含独立的执行器和随机数状态。它们都不能由两个任务同时调用。

`SpeechRuntime` 顺序构建模型布局及所有上下文，之后将权重只读共享。`BoundedInferencePool<TContext>` 为每个上下文启动一个消费循环，通过有界 `Channel` 接收任务；单个上下文始终串行执行。ASR 和 TTS 使用不同的队列及请求配额。

多发音人 TTS 的每个工作上下文拥有按 `voiceId` 索引的执行器集合。174 个 AISHELL3 编号只选择同一模型的发音人嵌入，不复制 174 份权重，也不增加 174 个工作线程。所有音色共享一个 TTS 队列和入口配额；权重及 AISHELL3 词典共享只读存储，随机状态按上下文隔离。8kHz 电话输出复用 AISHELL3 的模型结果数组，避免无意义的重采样和整段复制。

多个 WebSocket 会话各自拥有音频解码、重采样、VAD 历史、32 秒环形缓冲、句段队列与事件序列。每个会话最多保留四个等待中的最终句段和一个可替换预览；超过限制明确结束请求，避免无界增长。预览失效后不会作为另一个会话的结果发送。

默认配置：

| 配置键（`Speech:`） | 默认 | 含义 |
|---|---:|---|
| `Threads` | 4 | 每次算子的最大线程数 |
| `AsrWorkers` | 1 | 独立识别上下文数量 |
| `TtsWorkers` | 1 | 独立合成上下文数量 |
| `QueueCapacity` | 8 | 每种推理等待队列上限，不含执行中的任务 |
| `MaxSessions` | 4 | 同时接收音频的实时连接数 |
| `MaxUploads` | 2 | 正在接收、排队或处理的 WAV 请求数 |
| `MaxTtsRequests` | 4 | 合成请求数，含网络发送阶段 |
| `ReceiveTimeoutSeconds` | 120 | 实时连接没有输入时的超时 |

HTTP 配额或推理队列已满返回 429。WebSocket 握手前超过会话限制返回 429；握手后因音频积压或推理失败结束连接，不能再返回 HTTP 429。客户端应监测 `done` 和关闭状态，保留自己需要重试的业务音频。

算子内部的持久线程组按线程数共享，并对任务发布进行同步。因此增加上下文数量不保证算子级线性扩展，尤其 RK3588 的四个大核可能已被一个上下文充分使用。默认值优先保持单请求速度；多路实时容量应使用实际电话录音进行持续测试。

## 取消语义

排队任务收到取消后立即结束调用方等待，消费线程看到已取消状态后跳过计算。已经开始的纯 CPU 推理不能安全地强制中断：取消会在计算结束后传播，调用方仍须等待其完成才能归还音频。这样可以避免 `ArrayPool` 数据归还后被其他连接覆盖而产生串音或内存竞态。

客户端断开会取消排队工作；会话释放时清理未消费的音频租约，并等待正在计算的句段结束。工作池停止接收后排空已接受任务。单次计算异常只影响相应任务，消费线程继续处理后续任务。

## 已消除或减少的拷贝

| 路径 | 实现 | 仍需的存储或拷贝 |
|---|---|---|
| PCM16 帧输入 | 小端且对齐时 `MemoryMarshal.Cast<byte, short>` 借用网络视图 | 转换后的 float 数据需要输出区 |
| G.711 与跨字节帧 | 会话复用 short/float 缓冲，Span 重载写入调用方输出 | 编解码与重采样需要数值转换 |
| WebSocket | 每连接租用固定大小输入/解码缓冲，消息序列化复用 `ArrayBufferWriter` | 网络、TLS 和 JSON 写入并非零分配 |
| WAV 上传 | 64 KiB 池字节缓冲逐块读取，直接解码到最终 float 数组 | 最终采样数组；采样率不同时还需重采样结果 |
| 句段推理 | 从环形缓冲复制到 `PooledAudioBuffer`，明确租约生命期 | 这份快照是异步排队期间必须持有的数据 |
| 重采样 | 预先计算最终长度，直接填充结果数组 | 输出采样数组；相同采样率直接复用输入 |
| TTS 网络输出 | 直接向 `HttpResponse.BodyWriter` 编码 WAV/PCM/G.711 | 模型浮点结果、重采样结果仍存在 |
| ASR 临时张量 | 同步作用域内复用精确长度数组 | 跨作用域输出和跟踪快照不归还该池 |
| TTS 临时张量 | 每执行器最多保留 64 MiB；最后一个数组视图结束后回收 | 返回结果脱离回收集合，开启 Trace 时禁用复用 |

PCM 解码稳态的零托管分配测试只覆盖 `PhoneAudioDecoder.Decode(bytes, destination)` 循环，不能推广为整条 HTTP/WebSocket 请求零分配。兼容性的返回数组重载仍会分配；新服务与实时 CLI 均使用调用方缓冲重载。

TTS 长文本完整响应仍需合并段落数组。需要较低首段等待时间时使用 `/tts/stream`，并由 SIP 层按 20 ms 节奏送入媒体端口。队列和网络配额同时限制内存增长，但不会消除模型和 KV 缓存的常驻成本。
