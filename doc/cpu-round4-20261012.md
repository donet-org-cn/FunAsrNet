# 本机 CPU 第四轮优化：ASR 接近原版（2026-10-12）

保持纯 C# 推理，在 i7-12700 本机继续优化。三条固定 ASR 样例比同轮上一版减少 **12.0%–22.4%** 耗时，与原版 C++ CPU 的耗时比为 **0.969–1.029**。这组热态样例已基本持平，不能推广为所有语料、尾延迟或其他 CPU 均持平。

**TTS 尚未追平。** 两种模型仍约为原生 ORT CPU 的 **1.46 倍耗时**。Huayan 中位数减少 1.8%，AISHELL3 增加 2.4%；结合块间波动，本轮不宣称 TTS 有明确速度提升。也没有达到原版一半耗时。

## 条件与计时边界

- Windows x64、Intel Core i7-12700、.NET 10.0.12、四线程、亲和性 `0x55`。正式测量关闭 GPU、性能跟踪和 ASR 提示词缓存。
- ASR 使用相同 F16 编码器、Q8_0 解码器和音频，最大 128 token。原版固定 Fun-ASR `0339018ba74a7defa3b6b6a96718d17b816be77b`、llama.cpp `8086439a4cea94c71a5dfb8fe4ad1546aebd640f`；MSVC 19.44、AVX2/FMA/AVX-VNNI、OpenMP、GPU 层数零。
- TTS 使用相同音素 ID、语速 1、两项随机度 0。原版对照为 ORT 1.23.2 CPU，intra-op 4、inter-op 1、顺序执行、全部图优化。
- ASR 计特征、编码、解码的完整调用；TTS 只计模型 Run。排除模型加载、输入读取、输出文件写入、文本前端和重采样，不是冷启动、完整服务请求延迟或并发容量。
- 第一组采用“上一版、本次、原版、原版、本次、上一版”六个独立进程块，每块预热一次，短 ASR/TTS 正式五次、长 ASR 三次，共 138 次正式、30 次预热。
- 初始 AISHELL3 旧版块出现 0.088–0.183 秒的明显波动，因此追加固定轮数 TTS 确认组，顺序为“原版、本次、上一版、上一版、本次、原版”，每块预热一次、正式十次。增加 120 次正式、12 次预热。表格合并全部初始及确认样本，**共 258 次正式、42 次预热**；没有删掉初始慢样本。

原始逐次数据、分阶段耗时、分配量、峰值 RSS、版本及散列见 [summary.json](benchmarks/20261012-cpu-round4/summary.json)。初始组与确认组分目录保留。固定模型和样例以 SHA-256 核对，见 [input-model-sha256.json](benchmarks/20261012-cpu-round4/validation/input-model-sha256.json)。

## 保留的实现

1. x64 激活量化每次处理 32 项，以 AVX2 求最大绝对值和舍入。采用“先截断，再判断小数部分”的远离零舍入，避免简单加减 0.5 导致半整数相邻浮点数错误进位。非有限值、倒数溢出的块保留标量语义；量化字节和缩放值与原标量逐位一致。
2. 单帧 Q8 一次处理四个输出行，多帧 Q8 一次处理四帧，共享整数归约并以四路浮点执行缩放。保留每 32 项的乘法和累加顺序，支持权重含 -128，AVX-VNNI 不可用时继续使用 AVX2 精确点积。
3. x64 FP32 矩阵完整四行块把输出尾部判断移出内层循环，长内积由 32 项分段改为 128 项，减少中间结果写回。模型精度没有改变，但浮点分组顺序改变，因此按独立参考误差、完整转写和波形阈值验收，不宣称所有浮点结果逐位相同。
4. 大张量的通道广播与现有同形逐元素运算一样分块并行。TTS 同形/标量广播加减乘除、LeakyRelu 在独占且最后一次读取时复用临时数组；调用方输入、常量、共享视图和返回结果禁止覆盖。观察回调开启时禁用原地操作。
5. TTS 每执行器空闲张量缓存由 64 MiB 提高到 128 MiB，按需增长。Huayan 每次托管分配中位数由 **83,979,784 降至 17,012,808 字节，减少 79.7%**；本轮进程峰值 RSS 最大值由约 367 降到 298 MiB。AISHELL3 分配约 8.3 MB，基本不变。缓存上限不是进程内存上限，多执行器需要分别预算，见 [并发与内存](concurrency-and-memory.md)。这项分配改善不代表相同比例的延迟改善。

诊断开关：`FUNASRNET_SCALAR_QUANTIZE=1` 回退 x64 激活量化；`FUNASRNET_Q8_ROWS4=0` 回退单帧四行内核；`FUNASRNET_AVX2_Q8=0` 回退整个 x64 Q8 路径；`FUNASRNET_AVX_SEGMENT128=0` 恢复长内积 32 项分段；`FUNASRNET_INPLACE_TTS=0` 关闭原地逐元素计算。正式数据采用默认设置，只有 ASR 提示词缓存按公平对照要求关闭。

## SimdPaddleOCR、`.comp` 与 `.spv`

[SimdPaddleOCR](https://github.com/sdcb/SimdPaddleOCR) 的 CPU 布局与分块设计可以参考；本轮试验了六输出通道块、逐层转换通道连续布局。直接增加块宽没有稳定收益，逐层布局转换使本机 TTS 变慢，均未保留。后续若继续尝试通道连续布局，需要让相邻算子沿用布局，减少来回转换，并重新实测。

这里的 `.comp` 是 GLSL 计算着色器源码，`.spv` 是离线编译得到的 SPIR-V，由 Vulkan 驱动在 GPU 上执行；它不是 C# CPU 优化，也不是 Native AOT。现有 Vulkan 设备基础设施已经按该项目的 Apache-2.0 许可引入，保留来源和许可，见 [第三方说明](../THIRD_PARTY_NOTICES.md)。本轮 CPU 内核独立实现，没有新增原生推理依赖。矩阵分块也参照了 [ORT MLAS 的 SGEMM 设计](https://github.com/microsoft/onnxruntime/blob/main/onnxruntime/core/mlas/lib/sgemm.cpp)，未把其原生代码链接到产品。

## 验证与适用范围

Release 构建零警告、零错误。默认和禁用 AVX-VNNI 分别通过 **3,052,338 项**检查；禁用 AVX2 后通过 **2,972,708 项**。新增检查覆盖量化半整数及其相邻浮点数、极小值、NaN/无穷、广播尾部、左右操作数原地减除、并行尾块、视图别名、跨调用输出和异常恢复。现有 Q8 极值逐位检查及 FP32 独立参考继续通过。

三方 ASR 的三份正式转写逐字相同。两种 TTS 长度一致且全部有限，与 ORT 的最大绝对误差及 RMSE 均通过既有 `0.001` / `0.0001` 阈值，数值见 summary 的 `ttsParity`；没有放宽阈值。Huayan 与旧版波形逐位相同，AISHELL3 因 FP32 分段变化存在阈值内误差。

完整本机服务 **46 项 DemoChecks**、AISHELL3 全部 **174 位发音人的 530 项检查**、**134,474 项 GPU 数值检查**通过；三份 GPU ASR 转写与上一版相同，两种 GPU TTS 与本次 CPU 波形对照通过。这些回归轮次不计入正式 CPU 性能样本。

仅验证 Windows x64。本轮没有部署或重启 RK3588，没有把固定样例一致性解释为浏览器麦克风真实识别率提高。此前 AOT/GPU 报告是各自源码和计时条件下的历史结果，本轮没有重做 AOT 性能对照。默认 CPU 始终由 C# 执行，原生 C++/ORT 只用于隔离的对照工具。
