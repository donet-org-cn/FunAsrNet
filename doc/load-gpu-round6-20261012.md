# 模型加载与 GPU 第六轮对比（2026-10-12）

相对 `9a75d600ab278663bc86aa75013cba933306516e`，本轮明显改善 GGUF 加载，并缩小 Vulkan 与原版 GPU 的耗时差距。默认 CPU 推理仍是纯 C#；没有增加原生 CPU 推理依赖。原版仅作为隔离的开发参照。

## Python 清理与复测

删除当前版本中六个 Python 编排/汇总脚本：第四轮三个、第五轮两个、AOT 一个。它们原本只服务于开发复测，不在产品推理路径内；现在统一使用 [C# 对比入口](../tools/FunAsrNet.Compare/README.md)。旧报告链接同步调整，原始 JSONL、统计结果和历史来源 manifest 不改写；历史散列索引只移除已删除脚本条目。Git 历史不重写。

新工具按参数列表启动子进程，原样保存 UTF-8 输出，验证样本数、优化前后转写及 TTS 波形，记录模型、输入和被测二进制散列。此次正式结果全部由这个入口产生，不使用 Python。

## GGUF 加载

同机 Windows x64、i7-12700、.NET 10.0.12，亲和性 `0x55`。每次新进程先后创建 F16 编码器和 Q8_0 解码器的 `Gguf`；ABBA 顺序循环三次，每版六个样本，无预热。文件缓存未清空。

| 项目 | 上一版 | 本次 |
|---|---:|---:|
| 两份模型读取及解包中位数 | 3.203 秒 | 0.723 秒 |
| 最近秩 P95 | 3.323 秒 | 0.739 秒 |
| 托管分配量中位数 | 3.076 GB | 1.812 GB |
| 进程峰值工作集的中位数 | 2.674 GB | 1.848 GB |

加载耗时减少 **77.4%**，约 **4.43 倍**速度；分配减少约 **41.1%**。GB 按十进制字节换算。此表不含进程启动、模型对象进一步初始化、推理、GPU 首次上传和服务就绪，不是冷盘或首次请求时延。

主要瓶颈是解码器 Q8 缩放逐项 Half 转换。对正规数直接展开指数、尾数和符号，对非正规数、NaN、无穷、正负零沿用 .NET 转换；原量化字节和缩放结果不变。F16/Q8 改成有界池缓冲分块读取，避免额外保留整个源张量字节副本。没有持久化解包缓存、模型重新量化或外置推理库。

完整 ASR 基准另外记录加载阶段和首个未预热调用。短 PCMA 的 CPU 对照如下，每格两个独立进程样本；这部分是启动观察，样本数比热态少：

| 阶段 | 上一版 C# CPU | 本次 C# CPU | 原版 C++ CPU |
|---|---:|---:|---:|
| 基准模型初始化 | 3.259 秒 | 0.798 秒 | 0.325 秒 |
| 初始化 + 首次转写之和 | 4.061 秒 | 1.606 秒 | 1.168 秒 |

这里不含进程启动，也不是 Web 服务就绪时延；原版使用自己的 GGUF/mmap 加载方式。GPU 同样例的初始化与首次转写之和为 6.062 → 3.596 秒，原版 CUDA 1.001 秒。GPU 首次调用还要上传权重，不能拿 0.723 秒读取时间代表首次 GPU 请求。

## GPU 热态对照

RTX 3060 12 GB；同模型、输入、四个 CPU 线程和 `0x55` 亲和性。ASR 双方关闭提示词缓存。顺序 before/after/native/native/after/before，每个进程一次预热、五次正式测量，每格十个样本。共 **150 次正式模型调用、30 次预热**，全部保留；小样本最近秩 P95 等于最大值。

| 项目 | 上一版 C# Vulkan | 本次 C# Vulkan | 同轮原版 GPU | 本轮耗时减少 | 本次 / 原版 |
|---|---:|---:|---:|---:|---:|
| ASR 6.000 秒 PCMA | 0.495 秒 | 0.427 秒 | 0.107 秒 | 13.8% | 4.00 倍 |
| ASR 5.616 秒 PCMU | 0.553 秒 | 0.480 秒 | 0.125 秒 | 13.2% | 3.84 倍 |
| ASR 28.000 秒重复样例 | 1.926 秒 | 1.640 秒 | 0.275 秒 | 14.8% | 5.97 倍 |
| TTS Huayan 0 号 | 0.229 秒 | 0.175 秒 | 0.029 秒 | 23.3% | 6.10 倍 |
| TTS AISHELL3 50 号 | 0.130 秒 | 0.095 秒 | 0.025 秒 | 27.0% | 3.87 倍 |

原版 ASR 为固定 Fun-ASR/ggml 原计算图的编码器与解码器 CUDA 路径；TTS 为 ORT 1.23.2 CUDA，关闭 TF32。构建来源和适配边界沿用 [原版 GPU 对照](gpu-native-comparison-20261012.md)。TTS 计相同音素输入的模型执行，语速 1、随机度 0，排除文本前端、播放和模型读取；ASR 计完整转写调用。

ASR GPU 三方转写逐字一致；新旧 C# GPU 的生成 token 数保持不变。短 PCMA 的 GPU 结果仍比 CPU 结果少句号，是已有路径差异，不将 CPU/GPU 输出长度差异计成本轮优化。两种 TTS 新旧 GPU 波形位结果相同；相对 ORT CUDA，最大绝对误差分别不超过 2.09e-5 / 3.52e-5，长度及原阈值均通过。没有降低计算精度或放宽验收阈值。

GPU 改动：

1. Q8_0 每个 32 元素块由八条 GPU 通道协同读取、整数求和，保持浮点分组累加顺序；完整子组和 shuffle 特性查询通过才启用，其他设备回退原内核。
2. FP32 共享内存布局转置并填充，K 分块从 16 到 32，减少 bank 冲突和工作组屏障；继续使用原 FP32 FMA/独立乘加规则。
3. 主机可见输入、临时权重和回读缓冲持久映射，保留传输屏障、flush/invalidate 和完成栅栏。
4. ONNX 动态 MatMul 与转置卷积临时矩阵使用可复用上传缓冲，避免逐次申请长期显存缓存和额外上传提交。稳定模型权重仍有界驻留。

编译器为 glslang 16.6.0，参数 `-V --target-env vulkan1.1 -S comp`，源码字符串及 SPIR-V 均嵌入 C#，运行时不需要编译器。[Vulkan 完整子组要求](https://docs.vulkan.org/refpages/latest/refpages/source/VkPipelineShaderStageCreateFlagBits.html) 与 [GLSL 子组交换定义](https://raw.githubusercontent.com/KhronosGroup/GLSL/master/extensions/khr/GL_KHR_shader_subgroup.txt) 用于核对子组内核边界。

**GPU 尚未追平原版。** 当前是 Vulkan 混合执行，短 ASR 一次仍有 294 次 FP32 和 904 次 Q8 同步调用，大量中间数据返回 CPU；原版权重/图调度、CUDA 算子实现不同。不能将此表解释为 C# 与 C++ 的语言性能差异，也不能推广到 RK3588 Mali。后续主要空间在连续算子驻留 GPU 和减少提交/同步，而非只增加权重缓存；当前 ASR 权重约 1.60 GB，已在默认 2 GiB 缓存内。

## CPU 回归与正确性

CPU 使用同样 ABCCBA 顺序，每进程一次预热、三次正式测量，每格六个样本。共 **126 次正式调用、42 次预热**。本轮主要优化加载和 GPU，CPU 热态没有新内核变化。

| 项目 | 上一版 C# CPU | 本次 C# CPU | 同轮原版 CPU |
|---|---:|---:|---:|
| ASR 6.000 秒 PCMA | 0.713 秒 | 0.718 秒 | 0.776 秒 |
| ASR 5.616 秒 PCMU | 0.826 秒 | 0.843 秒 | 0.896 秒 |
| ASR 28.000 秒重复样例 | 2.888 秒 | 2.903 秒 | 3.041 秒 |
| ASR 6.000 秒原始 PCM | 0.675 秒 | 0.668 秒 | 0.731 秒 |
| ASR 官方 PCMA | 0.669 秒 | 0.673 秒 | 0.735 秒 |
| TTS Huayan | 0.145 秒 | 0.142 秒 | 0.108 秒 |
| TTS AISHELL3 | 0.068 秒 | 0.067 秒 | 0.046 秒 |

CPU 热态中位数相对上一版约 -2.1%～+2.0%，没有一致的进一步加速；同轮 ASR 仍略快于原版，TTS 尚未追平 ORT CPU。五份 ASR 转写三方一致，两份额外输入只是短句的格式变体。TTS 新旧 CPU 波形及 ORT 误差均通过。

完整解决方案 Release 构建零警告、零错误；数值检查默认 **9,373,113** 项、禁用 AVX2 **9,178,432** 项通过，覆盖全部 65,536 种 Half 位模式、Q8 字节、GGUF 分块边界及截断输入。GPU 新内核与强制回退各 **139,808** 项通过，包含 Q8 新旧内核逐位比较和临时矩阵内容变化/扩容。独立本机服务检查 **46** 项、174 位发音人的 **530** 项检查通过；验证结束后关闭本轮测试服务。中文注释与格式检查零错误。
