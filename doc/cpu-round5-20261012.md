# 本机 ASR CPU 第五轮优化与实时等待（2026-10-12）

继续保持纯 C# 推理，重点优化 ASR。五份固定音频的本轮热态中位数比同轮上一版减少 **4.1%–6.9%** 耗时，为原版 C++ CPU 的 **0.906–0.939 倍**。五份音频的上一版、本次与原版转写逐字一致，未通过少输出 token 获取表中的提升。

另修复实时识别中无用预览排队及浏览器结束通知等待。模型执行时间和用户停止录音后的等待是两个口径，以下离线 CPU 表不包含实时调度收益。

## 保留与撤回的实现

- x64 Q8 多投影只量化一次公共输入，Q/K/V 和 Gate/Up 共用临时池缓冲，输出行合并到一次线程组分派。四行／四帧点积保持每 32 项的缩放、乘法及累加顺序，逐位对照独立标量参考。
- x64 FP32 矩阵保留四行乘十六帧和原有 K128 分段。提前准备四条权重行地址，内循环展开两项并递进地址，保持每个累加器的 FMA 次序。编码中位数由 PCMA 的 0.225 降到 0.189 秒，28 秒样例由 1.149 降到 1.017 秒；解码改善较小，仍是后续重点。
- F16 权重读取向量化展开为 FP32，穷举全部 65,536 个 Half 位模式，包含负零、非正规数与 NaN 载荷。权重值与原 .NET cast 逐位相同。这只影响模型读取，不计入热态推理提升。
- TTS 的独占相邻 `Conv→Add`、`Conv→LeakyRelu` 在卷积写回时完成后处理，保留 `(FMA sum + bias) + residual` 顺序。中间值为模型输出、有其他消费者、残差广播、Trace/NodeMeasured 或可选后端开启时继续使用原节点。
- 末两维转置采用 AVX2 八乘八寄存器块和三十二乘三十二缓存块，保留所有位模式；多轴 Pad 按连续行复制，避免逐元素计算高维坐标，大输出按独立行并行。

**256 项分段未保留为默认优化。** 尽管数值误差检查通过，完整转写发现 PCMA 短句少了末尾句号，并少生成一个 token。这会直接减少解码工作量，所以它的低耗时不能全部归因于内核提速，未纳入本页正式表格。512 项分段超过既有 FP32 误差阈值，已撤回。卷积 tap 展开与时间优先任务顺序的组合出现退化，也未保留。没有放宽数值或波形阈值。

诊断开关：`FUNASRNET_Q8_GROUPED=0` 关闭共享多投影；`FUNASRNET_AVX_UNROLL=0` 关闭 FP32 循环展开；`FUNASRNET_AVX_SEGMENT128=0` 恢复旧长内积 K32，`=1` 采用 K128；`FUNASRNET_SCALAR_HALF_LOAD=1` 使用原 Half 加载转换；`FUNASRNET_FUSE_CONV=0` 关闭图级卷积融合；`FUNASRNET_AVX_TRANSPOSE=0` 和 `FUNASRNET_LEGACY_PAD=1` 可对照原布局算子。正式数据使用默认优化，双方按公平对照要求关闭 ASR 提示词缓存。

## 实时识别额外等待

浏览器默认开启预览，当前预览仍每 1.5 秒从句段起点完整重跑一次 ASR，不是增量编码器。最终句还要执行完整识别，因此实际等待不能由单次离线 Transcribe 的秒数解释。

此前最终句只清除尚未取走的预览；预览进入全局池后即使结果已经过期，也会继续排队。现在每个预览有独立的关联取消令牌，新预览、最终句、Complete 和 Dispose 会取消过期预览。尚未执行的池任务被跳过；正在执行的同步 CPU 任务仍等待返回后才归还音频，不会让其他会话覆盖它正在读取的池缓冲。仅吞掉对应预览的局部取消，会话取消和其他异常继续传播。

受控真实工作池检查确认：池被其他工作占用时，结束录音会取消排队预览，随后只执行最终识别，不执行已失效的预览；另检查运行中输入所有权、预览替换、最终事件顺序和会话取消。该检查验证调度行为，不把模型 CPU 性能表包装成实时停止延迟保证。

浏览器在 AudioWorklet 确认尾帧已经发送后立即发送 `end`，随后等待设备清理。停止计时从点击时开始，包含尾帧刷新和清理期间的等待。受控 JS 检查验证 `尾部 PCM → end → AudioContext.close` 顺序及清理完成，原有“停止后完成”计时不再遗漏点击后的这段时间。

## 条件、验证与来源

Windows x64、i7-12700、.NET 10.0.12、四线程、亲和性 `0x55`。上一版为 `3a6105931c37fc2cbe027987930d3c388d7db730`，本轮与原版交替执行，未把旧报告绝对秒数拼接为新的提升。

ASR 原版固定 Fun-ASR `0339018ba74a7defa3b6b6a96718d17b816be77b`、llama.cpp `8086439a4cea94c71a5dfb8fe4ad1546aebd640f`，MSVC 19.44、AVX2/FMA/AVX-VNNI、OpenMP、GPU 层数零；相同 F16/Q8_0 模型、音频、最大 128 token。TTS 原生对照为 ORT 1.23.2 CPU，intra-op 4、inter-op 1、顺序执行、全部图优化；相同音素、语速 1、随机度 0。

每输入六个独立进程块，顺序为“上一版、本次、原版、原版、本次、上一版”。每块预热一次；四条短 ASR 每块正式五次，28 秒 ASR 三次，两个 TTS 模型十次。合计 **258 次正式、42 次预热**。ASR 计特征、编码和解码的完整调用；TTS 只计模型 Run。均排除读取、模型加载、前端、输出文件写入和重采样，不是首次请求延迟。TTS 每实现每模型 20 次，其最近秩 P95 是第二大值。

模型加载仍有明显差距：本轮 C# 加载记录约 3.2 秒、C++ 约 0.3 秒，双方加载路径及内存表示不同，未清空文件缓存。热态样例快于原版不代表首次启动也持平，尚未达到原版一半耗时，也不能保证其他语料或 CPU 的结果。

Release 构建零警告、零错误；默认与禁用 AVX-VNNI 分别通过 **7,210,419 项**检查，禁用 AVX2 通过 **7,015,738 项**。五份正式 ASR 转写逐字一致，两种 CPU TTS 与上一版波形逐位一致，与 ORT 的波形误差通过既有阈值。完整本机服务 **46 项 DemoChecks**、全部 **174 位发音人的 530 项检查**、**134,474 项 GPU 数值检查**通过；三份 GPU ASR 与上一版一致，两种 GPU TTS 与本次 CPU 对照通过。回归轮次不计入正式 CPU 性能表。

本轮只验证本机 Windows x64，未部署或重启 RK3588，未重做 AOT 或 GPU 性能比较。历史 AOT/GPU 数据保留为各自源码快照。
