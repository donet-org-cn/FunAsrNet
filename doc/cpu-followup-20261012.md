# 本机 CPU 继续优化与原版对比（2026-10-12）

**本页为前轮历史快照。** 当前 Windows CPU 的最新优化和原版对照见 [本机 ASR 第五轮记录](cpu-round5-20261012.md)；本页数字不代表最新构建。

按本次要求只在本机测试。默认 C# ASR 比上一版耗时减少约 19–33%，TTS 减少约 41–44%。ASR 已缩到原版 CPU 的 1.21–1.40 倍耗时；TTS 为同模型 ORT CPU 的 1.71–1.79 倍。**尚未全部持平，也没有达到原版一半耗时。** 如果“差距 0.5 倍”指至多慢 50%，本轮 ASR 已达到，TTS 尚未达到。

## 相同条件下的完整调用

i7-12700、Windows x64、.NET 10.0.12，四线程、亲和性 `0x55`。优化前使用 `ab83e5b` 构建，优化后使用本次 CPU 改动。ASR 对照固定 Fun-ASR `0339018` 与 llama.cpp `8086439` 原计算图 CPU，MSVC 19.44、AVX2/FMA/AVX-VNNI、OpenMP；CUDA/Vulkan/BLAS 关闭。C# 本机也支持 AVX-VNNI，本次为原版重新启用该编译选项，避免只给一边使用该指令。

TTS 对照 ORT 1.23.2 CPU Provider，四个 intra-op 线程、一个 inter-op 线程、顺序执行与全部图优化。保持相同 Huayan 0 号、AISHELL3 50 号模型及音素输入，语速 1、两项随机度 0。ASR 保持同一 F16/Q8_0 权重，双方关闭提示词缓存，最大 128 token。

下表为热态中位数，单位秒。ASR 计完整特征、编码和解码；TTS 计模型 Run，排除文本前端、音频封装、重采样。均排除模型读取、文件写入及预热。

| 项目 | 优化前 C# CPU | 本次 C# CPU | 原生 CPU | 本次 / 原生 | C# 耗时减少 |
|---|---:|---:|---:|---:|---:|
| ASR 6.000 秒 PCMA | 1.401 | 0.945 | 0.740 | 1.28 倍 | 32.5% |
| ASR 5.616 秒 PCMU | 1.486 | 1.027 | 0.850 | 1.21 倍 | 30.9% |
| ASR 28.000 秒重复样例 | 5.249 | 4.237 | 3.031 | 1.40 倍 | 19.3% |
| TTS Huayan | 0.313 | 0.184 | 0.103 | 1.79 倍 | 41.2% |
| TTS AISHELL3 | 0.134 | 0.075 | 0.044 | 1.71 倍 | 44.3% |

每个输入按“优化前、优化后、原生、原生、优化后、优化前”六个独立进程块测量。每块预热一次，短 ASR/TTS 每块五次正式测量、长 ASR 每块三次；共 **138 次正式样本、30 次预热**。每实现的短句/TTS 十次、长样例六次；P95 最近秩，在这些样本量下等于最大值。完整 P95、分阶段统计、全部慢样本、模型和输入散列、两版程序集以及原生二进制散列见 [summary.json](benchmarks/20261012-cpu-next/summary.json)。未锁频，在线本机有背景负载，不将小样本外推为稳定尾延迟或并发容量。

本轮没有改动模型、缩短输入或更换权重量化。没有把原生 CPU 与 C# GPU 混算，也不将结果解释为语言优势。八线程两边均会更快，但仍未全面持平；十二线程在本机反而变慢，未作为默认配置或最终四线程表格的数据。

## 保留的改动

- x64 Q8 行主序投影使用 AVX2 字节乘加，支持时用 AVX-VNNI；四帧共享权重读取，保留每三十二项的整数点积、缩放次序及 FP32 累加次序。权重允许 -128，激活限制为 [-127,127]，不会发生短整数饱和。`FUNASRNET_AVX2_Q8=0` 可用于回退诊断。
- AVX2 直接卷积覆盖更多中短时间序列，完整内部块把填充与输出通道尾部判断放到内积外，保持原 FMA 顺序。边界、分组、膨胀和尾部仍走验证过的处理。`FUNASRNET_LEGACY_CONV=1` 回退直接卷积，`FUNASRNET_LEGACY_AVX_CONV_INNER=1` 回退内部块分支外移。
- 完整覆盖结果的算子不再先清零再写入；需要零填充或累加的输入工作区仍显式清零。大连续算术结果按独立区间并行，广播选择沿连续末维向量化，LeakyRelu 使用八元素向量；负零和 NaN 分支语义保留。`FUNASRNET_SERIAL_ELEMENTWISE=1` 可诊断算术并行收益。
- 常量平方使用 FP32 乘法；x64 sigmoid/erf 使用 .NET 的向量指数，erf 保留原双精度系数和运算顺序，其他平台保留标量路径。较短浮点内积减少中间累加器写回，长内积仍使用原三十二项分段。

没有收益的卷积面板、六输出通道扩展、偏移预计算及单 token 四行展开已撤回；未将其微基准或诊断轮次计入正式数据。只保留通过整体模型、数值和波形检验的改动。

## 精度和测试边界

三份 ASR 的优化前、优化后与原版 CPU 正式文本严格一致。这是固定样例回归，不是识别率或真实麦克风 CER/WER 评估。按本次优先级，浏览器实时切句和录音对照方案暂存于开发产物，未进入这次 CPU 提交；用户实际错字原因仍待同一录音定位。

TTS 输出长度相同、全部有限，保持最大绝对误差 `0.001`、RMSE `0.0001` 阈值：

| 模型 | 最大绝对误差 | RMSE |
|---|---:|---:|
| Huayan | 1.90 × 10⁻⁵ | 1.11 × 10⁻⁶ |
| AISHELL3 | 2.17 × 10⁻⁵ | 1.19 × 10⁻⁶ |

优化前/后波形比较也通过。新增检查涵盖 Q8 极值、-128 权重、带符号缩放和严格逐位标量一致性；并行大张量尾块与只读输入；广播选择的 NaN、负零；激活与双精度参考、独立数值积分以及无穷边界。本轮只验证 Windows x64，不宣称新的 ARM64 性能和服务结果。

Release 数值检查通过 **1,233,601 项**，强制禁用 AVX-VNNI 后的 AVX2 回退也通过相同检查；既有 134,474 项 GPU 数值检查、三份 GPU 转写回归和本机默认 CPU 的 46 项 DemoChecks 通过。本机 GPU 短句仍保留前轮已注明的句末标点差异，未用这轮回归重新宣称 GPU 性能。本轮代码没有部署到远端。服务检查数按 PASS 项计数，已更正此前把 61 行日志当作检查数的表述。

## 复测

准备模型与相同输入见 [模型清单](models.md)、[前轮纯 CPU 记录](cpu-native-comparison-20261012.md)。原生 CPU 生成器见 [NativeAsrCpuFixture.cs](../tools/FunAsrNet.NativeReference/NativeAsrCpuFixture.cs)。本机原生构建增加：

```text
cmake -S artifacts/native-cpu -B artifacts/native-cpu/build-vnni -G Ninja -DCMAKE_BUILD_TYPE=Release -DGGML_AVX_VNNI=ON
cmake --build artifacts/native-cpu/build-vnni --target funasr-native-cpu-reference --parallel 8
```

`GGML_AVX_VNNI=ON` 要求运行机器支持该指令，不用于其他 CPU 的通用二进制。C# 可用 `cpu-info` 查询实际支持，默认四线程；TTS 与原生 ORT 工具均支持 `--threads`，比较时两边保持一致。正式统计关闭 `--profile`。
